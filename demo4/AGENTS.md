# UI 与 Design System 同步维护

作用范围：本目录 `prototype-demo4` 及其子目录。

1. 开始 UI 任务时先读取 `DESIGN.md`、`docs/design-system/README.md`，以及对应组件、基础或模式文档。
2. 每次改变 UI 样式、Token、组件状态、交互、布局、主题或使用范围，必须在同一次任务中更新对应 Markdown；不能仅执行生成脚本代替人工更新规则。
3. 用户直接修改设计文档时，将修改视为设计意图。若与当前代码不一致，标注“待实现”并记录差异；只有用户同时授权实现时才改代码，不自动覆盖用户文档。
4. 新增 UI 名词时建独立文档，加入目录，写清状态、样式、适用范围、替代项、状态/键盘、真实源码和示例。不存在的变体与 React API 不得写成已实现。
5. 执行 `npm run docs:sync` 仅刷新生成区和快照，保留生成区之外的用户文本；不要修改源码快照来绕过语义文档维护。
6. 再运行 `npm run docs:check` 检查链接、Token 页面与源码漂移；相关 UI 在浏览器中做针对性验证。不要声称该检查已证明布局、对比度或无障碍全部正确。
7. 将可见设计变化写入 `docs/design-system/CHANGELOG.md`。记录日期、改了什么、原因、受影响条目和实际验证结果。
8. 需要改样式时核对 `src/styles/index.css` 导入顺序、选择器、媒体条件、主题及最终计算样式。历史未导入的 Fireworks/Crimson 文件不是当前默认规范。

9. 设计文档只填写有现存明确依据的规则，注明来源。代码实测值单列为实现记录，不自动视为已确认规范；不确定、冲突未解或来源仅为候选/建议的字段留空，不补全通用最佳实践、示例或组件 API。最新用户要求优先于模板完整性。
