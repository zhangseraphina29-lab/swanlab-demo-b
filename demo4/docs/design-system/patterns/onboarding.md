用户于 2026-11-26 要求：新用户创建组织引导页增加「加入组织」按钮。

用户于 2026-11-26 进一步要求：「加入组织」进入申请界面，申请后反馈等待管理员通过，组织管理员收到申请；添加成员仅保留链接邀请，移除邮箱邀请入口。此要求取代此前邀请说明弹窗。

实现记录：「我的组织」空状态和「创建新组织」表单均保留次要按钮。点击进入「申请加入组织」独立引导页，填写组织 ID、可选申请说明（最多 500 字）。不接受组织名称；组织 ID 不存在时显示持续错误。提交后隐藏申请表，仅在「我的申请」显示组织及待审核状态，明确提示等待组织管理员审核。同一账号已申请过的组织不允许重复申请，错误持续显示且不新增记录；申请不占成员名额。

管理员在组织概览看到待审核数量及查看入口，成员管理新增「加入申请」列表，展示姓名、邮箱、说明、精确到秒的申请时间、状态及通过/拒绝操作。两种审核均先确认；通过时检查管理员权限、名额和成员状态，新增成员默认组织贡献者，记录审核人及时间；拒绝不增加成员。申请人可查看未通过状态并联系组织管理员，已通过可进入组织。申请状态保存在组织的 joinApplications 中，重新登录可回到已有申请；通过后登录直接进入目标组织。

链接邀请继续沿用已有的角色选择、生成、复制、预览及撤销操作，不再显示邀请方式 Tab 或邮箱邀请表单。历史邮箱邀请数据保留，避免影响已发邀请。当前申请、审核与邀请均为同一浏览器本地原型数据，尚无跨浏览器服务通知。

源码：[申请与审核](../../../src/organization-applications.js)、[界面与事件](../../../src/controller.js)。

## 申请页入口与返回

用户于 2026-11-26 批注要求：提交后不再显示申请表，状态页增加「返回」；切换组织浮窗增加一行「加入组织」，进入同一申请流程。

实现记录：切换组织浮窗的创建组织下方提供加入组织入口，沿用菜单行样式。已有组织的用户使用当前账号申请，保留原组织及页面；申请页和提交后的状态页均可返回原页面。新用户返回「我的组织」引导。提交状态和申请记录持久保存，返回或重新登录后仍可查看；未通过时仍不允许重复申请。浮窗入口遵守已有未保存修改确认。

用户于 2026-11-26 最新批注：状态页「返回」右侧增加主按钮「继续申请」，打开申请表以申请其他组织。组织字段仅接受组织 ID。已申请的组织（含待审核、已通过及未通过）均不重复提交；现有成员同样不能再次申请其所在组织。此规则取代此前未通过后重新申请的实现。

## 链接邀请接收页

用户于 2026-11-26 要求：移除手机号邀请；补齐链接邀请的接收页面，未登录先登录或注册，完成后才显示邀请内容。当前添加成员仅保留链接邀请，无手机号邀请入口。

实现记录：打开 inviteLink 地址或点击「预览接受页面」进入独立组织邀请页。未登录显示现有登录 / 注册表单，邀请 ID 保留，组织及角色内容在登录后展示。新账号完成注册后先查看邀请，不自动创建组织或自动加入。邀请页展示当前账号邮箱、组织名称、角色、有效期和确认加入按钮，不提供可任意修改的接受邮箱输入框。接受时使用当前登录身份并重新校验链接、成员状态及容量；已有成员可进入组织且原角色不变。不存在、撤销或过期的链接显示不可用状态；登录后刷新仍保留邀请。原型数据仍限同一浏览器。

源码：[邀请身份与接受](../../../src/invitation-reception.js)、[接收页面](../../../src/controller.js)。
